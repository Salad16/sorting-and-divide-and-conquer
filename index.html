Topic 01 • Elementary Sorting

Selection Sort: The 'Find Minimum and Swap' Mechanism

Part 1 of 8
Definition to Explain in Class:

Selection Sort is an in-place comparison algorithm that repeatedly searches the unsorted portion of an array to find the minimum element, then swaps it with the first element of that unsorted portion.

Essential Keywords:
Minimum Element Sorted Subarray arr[0..i-1] Unsorted Subarray arr[i..n-1] In-Place Swap n - 1 Passes Unstable by Default
Talking Point

"Remember: Selection Sort makes a commitment in every pass—find the absolute minimum of what remains, and lock it into place with one swap!"

Why is it Unstable?

A long-distance swap can jump an element over its twin! For instance, in [4a, 4b, 2], swapping 2 with 4a gives [2, 4b, 4a]. The relative order of 4a and 4b was inverted.

function selectionSort(arr, n):
  for i = 0 to n - 2:           // n - 1 total passes
    min_idx = i
    for j = i + 1 to n - 1:     // Scan unsorted part
      if arr[j] < arr[min_idx]:
        min_idx = j
    swap(arr[i], arr[min_idx])  // Exactly 1 swap per pass

Topic 02 • Complexity Analysis

Selection Sort: Exact Mathematical Analysis & Invariance

Part 2 of 8
Total Comparisons Formula (Arithmetic Series)

In pass 0, it makes (n - 1) comparisons. In pass 1, (n - 2). In pass n - 2, 1 comparison:

C(n) = (n - 1) + (n - 2) + ... + 2 + 1 = n(n - 1) / 2 = O(n²)
Why Best Case is STILL O(n²):

Selection Sort has zero early exit conditions. Even if the array is already perfectly sorted, the inner loop must inspect every remaining element before confirming that arr[i] is indeed the minimum.

Board Note

"Selection Sort is completely indifferent to the initial state of the array. Best, Average, and Worst case comparisons are identical: exactly n(n - 1)/2."

Scenario Comparisons Swaps Time Space
Best Case (Already sorted) n(n - 1) / 2 0 O(n²) O(1)
Average Case (Random) n(n - 1) / 2 O(n) O(n²) O(1)
Worst Case (Reverse sorted) n(n - 1) / 2 n - 1 O(n²) O(1)
The One Big Advantage: O(n) Swaps!

While Insertion Sort can perform up to O(n²) data movements, Selection Sort executes at most n - 1 swaps. In hardware systems where memory write operations degrade the storage medium (such as EEPROM or flash), Selection Sort minimizes memory writes.

Topic 03 • Elementary Sorting

Insertion Sort: The 'Card In Hand' Shifting Mechanism

Part 3 of 8
Definition to Explain in Class:

Insertion Sort builds the final sorted array one element at a time. It picks the next element (the key) from the unsorted portion and slides larger elements in the sorted portion one slot to the right, inserting the key in its rightful position.

Essential Keywords:
Card Player Analogy Key Element (arr[i]) Right Shift (arr[j+1] = arr[j]) Adaptive (Early Exit) Online Algorithm Stable Sorting
Talking Point

"Contrast with Selection Sort: Selection Sort scans forward to find the minimum; Insertion Sort takes the next item and walks backward into the sorted hand to insert it!"

Why is it Stable?

When the key encounters an identical value, the backward shift condition arr[j] > key evaluates to false and stops. Equal elements maintain their exact original relative order!

function insertionSort(arr, n):
  for i = 1 to n - 1:              // Start at index 1
    key = arr[i]                   // Pick card
    j = i - 1
    while j >= 0 and arr[j] > key: // Shift larger items
      arr[j + 1] = arr[j]
      j = j - 1
    arr[j + 1] = key               // Insert key into slot

Topic 04 • GeeksforGeeks Grounded Reference

Insertion Sort: Time & Space Complexity Analysis

Part 4 of 8
Best Case: O(n) Time — [Already Sorted]

Occurs when the input array is already sorted (e.g., [1, 2, 3, 4, 5]). Each element is compared only once with the item immediately before it. No shifting is required.

Comparisons: n - 1 | Shifts: 0 | Time: O(n)
Average Case: O(n²) Time — [Random Order]

For each element, it compares and shifts some elements. On average, each element moves through about half of the elements in the sorted portion.

Total Shifts: n(n - 1) / 4 ≈ n² / 4 | Time: O(n²)
Worst Case: O(n²) Time — [Reverse Sorted]

Occurs when sorted in descending order (e.g., [5, 4, 3, 2, 1]). Each new element must be compared and shifted past all elements before it.

Total Work: 1 + 2 + ... + (n - 1) = n(n - 1) / 2 | Time: O(n²)
GeeksforGeeks Official Master Matrix

Direct comparison of comparisons, shifts, and memory overhead:

Case Comparisons / Shifts Time Auxiliary Space
Best Case n - 1 O(n) O(1)
Average Case ≈ n² / 4 O(n²) O(1)
Worst Case n(n - 1) / 2 O(n²) O(1)
Auxiliary Space Analysis (Per GeeksforGeeks):

Insertion Sort sorts in-place; it does not allocate an extra array. It requires only a few scalar variables such as key and j. Hence, extra memory remains constant: O(1) Auxiliary Space.

GFG Insight

"Insertion Sort is adaptive: its running time scales gracefully with the number of inversions in the array!"

Topic 05 • Algorithmic Paradigms

The Divide-and-Conquer Paradigm: Principles & Recurrence

Part 5 of 8
1. Divide (Split)

Break the original large problem into smaller, non-overlapping subproblems that are smaller instances of the same problem.

mid = (left + right) / 2

Usually cuts the input size in half, $n \to n/2$. Cost of division is typically trivial $O(1)$.

2. Conquer (Recurse)

Solve the subproblems recursively. If the subproblem size is small enough (the base case), solve it straightforwardly without further recursion.

if (left >= right) return;

A single element or empty list is already sorted! Base cases prevent infinite recursion.

3. Combine (Merge)

Merge or assemble the solutions of the smaller subproblems into the solution for the original larger problem.

merge(arr, left, mid, right)

In Merge Sort, all actual sorting happens here in linear $O(n)$ time!

Recurrence

"We model Divide-and-Conquer mathematically using recurrence relations: T(n) = a·T(n/b) + f(n), where 'a' is subproblems, 'n/b' is subproblem size, and 'f(n)' is divide/combine cost."

Divide-and-Conquer vs. Dynamic Programming:

Divide-and-Conquer applies when subproblems are independent and disjoint (no overlap). Dynamic Programming is used when subproblems overlap and need memoization.

Topic 06 • Divide-and-Conquer Sorting

Merge Sort: Two-Way Merging & Recursive Splitting

Part 6 of 8
Definition to Explain in Class:

Merge Sort is a recursive divide-and-conquer algorithm that continually divides an array into two equal halves until each subarray has only 1 element, then merges the sorted halves back together.

Midpoint Split Base Case (left >= right) Two-Pointer Merge Stable (L[i] <= R[j]) Guaranteed O(n log n) O(n) Auxiliary Array
The Two-Pointer Linear Merge O(n):

Maintain pointer i on left array and j on right array. Compare L[i] and R[j], copy the smaller to main array, and advance that pointer. Each element is examined once!

Talking Point

"Tell the class: An array of 1 element is already sorted by definition. Merge Sort breaks everything down to trivial size-1 arrays, then merges sorted pairs upward!"

function mergeSort(arr, left, right):
  if left < right:
    mid = (left + right) / 2
    mergeSort(arr, left, mid)        // Sort left half
    mergeSort(arr, mid + 1, right)    // Sort right half
    merge(arr, left, mid, right)      // Linear merge O(n)

function merge(arr, left, mid, right):
  create temp arrays L and R
  i = 0, j = 0, k = left
  while i < n1 and j < n2:
    if L[i] <= R[j]:                 // <= guarantees STABILITY!
      arr[k++] = L[i++]
    else:
      arr[k++] = R[j++]
  copy remaining elements of L and R into arr

Topic 07 • Recursion Tree & Complexity

Merge Sort Recursion Tree: Why it is Universally O(n log n)

Part 7 of 8
Recursion Tree Work per Level
Level 0: [ n ] Cost = c · n
Level 1: [ n/2 ] + [ n/2 ] Cost = 2 · c(n/2) = c · n
Level 2: 4 × [ n/4 ] Cost = 4 · c(n/4) = c · n
⋮ (log₂ n total levels of division)
Base Level: n × [ 1 ] Cost = n · c(1) = c · n
$$\text{Total Time} = (\log_2 n \text{ levels}) \times (c \cdot n \text{ work/level}) = \Theta(n \log n)$$
Recurrence Relation via Master Theorem:

The time complexity is governed by the recurrence:

$$T(n) = 2T(n/2) + \Theta(n)$$

Here, $a = 2$ (two subproblems), $b = 2$ (divided in half), and $f(n) = \Theta(n)$ (linear merge cost). Since $\log_b a = \log_2 2 = 1$, Case 2 of the Master Theorem applies: $\Theta(n^{\log_b a} \log n) = \Theta(n \log n)$.

Scenario Time Complexity Auxiliary Space Stability
Best Case Ω(n log n) O(n) Stable
Average Case Θ(n log n) O(n) Stable
Worst Case O(n log n) O(n) Stable

Topic 08 • Strategic Algorithmic Selection

Master Decision Matrix: How to Choose the Right Algorithm

Part 8 of 8
Algorithm Best Time Average Time Worst Time Auxiliary Space Stable? In-Place? Primary Superpower
Selection Sort O(n²) O(n²) O(n²) O(1) No Yes Minimizes writes (≤ n-1 swaps).
Insertion Sort O(n) O(n²) O(n²) O(1) Yes Yes Adaptive, online, blazingly fast on small/nearly sorted data.
Merge Sort O(n log n) O(n log n) O(n log n) O(n) Yes No Guaranteed O(n log n) worst-case time & stable.
When to Pick Insertion Sort

Small arrays ($n < 50$), data that is already almost sorted, or streaming data arriving continuously one item at a time.

When to Pick Selection Sort

Embedded systems or EEPROM flash memory where disk write cycles wear down physical storage ($O(n)$ maximum writes).

When to Pick Merge Sort

Large datasets requiring strict $O(n \log n)$ upper bounds, sorting linked lists (where extra space is $O(1)$), or multi-attribute stable sorts.

Industry Fact

"Why choose between them? Python's sorted() and Java's Arrays.sort() use TIMSORT—a hybrid that splits data into chunks, sorts them with Insertion Sort, and merges them with Merge Sort!"
