Selection Sort Algorithm Correct Key: A

#01. Which statement accurately describes the core operating mechanism of the Selection Sort algorithm on an unsorted array?

A It repeatedly scans the unsorted subarray to find the minimum element and swaps it to the front. ✓ Correct Answer
B It repeatedly compares and swaps adjacent out-of-order pairs until no inversions remain.
C It takes each element sequentially and shifts larger preceding elements right to insert it into place.
D It divides the array into two halves, recursively sorts them, and merges them together.
Step-by-Step Rationale & Proof:

Selection Sort maintains two subarrays: a sorted prefix and an unsorted suffix. In each pass, it scans the unsorted portion to locate the smallest element and swaps it with the first unsorted position.

💡 Classroom Talking Point:

Classroom Mantra: 'Select the absolute minimum of what remains, and lock it into place with one swap!'

Selection Sort Algorithm Correct Key: C

#02. For an array with n elements, what is the exact number of outer loop passes required by Selection Sort to guarantee the entire array is completely sorted?

A n passes
B n / 2 passes
C n - 1 passes ✓ Correct Answer
D log2(n) passes
Step-by-Step Rationale & Proof:

Selection Sort requires exactly (n - 1) outer loop passes. Once the first (n - 1) smallest elements are placed into their correct indices 0 through n - 2, the remaining single element at index n - 1 is mathematically guaranteed to be the maximum and already in its proper position.

💡 Classroom Talking Point:

If you have 5 cards and place the 4 smallest in order, the 5th card is guaranteed to be in its correct final spot.

Selection Sort Algorithm Correct Key: B

#03. Consider the array [4a, 4b, 2], where 4a and 4b have equal values. After the first pass of standard in-place Selection Sort, the array becomes [2, 4b, 4a]. What fundamental property does this demonstrate?

A Selection Sort is adaptive because it detects identical values.
B Selection Sort is UNSTABLE because a long-range swap can invert the relative order of duplicate keys. ✓ Correct Answer
C Selection Sort achieves optimal O(n log n) comparisons on duplicate keys.
D Selection Sort requires extra auxiliary memory proportional to the number of duplicates.
Step-by-Step Rationale & Proof:

In standard array-based Selection Sort, finding the minimum (2) at index 2 causes a swap with the element at index 0 (4a). This long-distance swap causes 4a to jump over 4b, reversing their original relative order from (4a, 4b) to (4b, 4a). Thus, standard Selection Sort is inherently unstable.

💡 Classroom Talking Point:

Classroom visual: Long-distance swaps jump right over duplicate twins, permanently destroying initial relative order.

Selection Sort Algorithm Correct Key: D

#04. In the inner loop of Selection Sort during pass i (where 0 <= i < n - 1), how many element comparisons are executed?

A Exactly i comparisons
B Exactly n comparisons
C floor(n / 2) comparisons
D Exactly n - 1 - i comparisons ✓ Correct Answer
Step-by-Step Rationale & Proof:

In pass i, the inner loop index j runs from i + 1 up to n - 1. The total number of iterations is (n - 1) - (i + 1) + 1 = n - 1 - i. For example, at pass 0 it performs n - 1 comparisons; at pass n - 2 it performs exactly 1 comparison.

💡 Classroom Talking Point:

At pass i, the scan window only looks at elements to the right of index i, shrinking by 1 comparison each pass.

Selection Sort Time Complexity Correct Key: A

#05. Why does Selection Sort exhibit a Best-Case time complexity of Θ(n²) even when the input array is already completely sorted?

A It lacks an early-exit check and must scan every remaining unsorted element to confirm the minimum. ✓ Correct Answer
B It performs n(n - 1) / 2 element swaps regardless of initial order.
C Its recursion stack always expands to depth n.
D It allocates O(n²) temporary memory buffers before processing begins.
Step-by-Step Rationale & Proof:

Selection Sort has zero early-termination conditions. Even if the array is already in perfect ascending order, the inner loop must still inspect every remaining element before confirming that arr[i] is indeed the minimum of that pass. Thus, it always makes n(n - 1)/2 comparisons, yielding Θ(n²).

💡 Classroom Talking Point:

Selection Sort is completely 'order-blind'—it does the exact same work whether the list is already sorted, reversed, or random.

Selection Sort Time Complexity Correct Key: C

#06. What is the exact formula for the total number of element comparisons performed by Selection Sort on an array of size n?

A n - 1 comparisons
B n² comparisons
C n(n - 1) / 2 comparisons ✓ Correct Answer
D n log2(n) comparisons
Step-by-Step Rationale & Proof:

The total number of comparisons is the sum of the arithmetic series (n - 1) + (n - 2) + ... + 2 + 1. By Gauss's summation formula, this equals n(n - 1) / 2 comparisons, regardless of input distribution.

💡 Classroom Talking Point:

Show the arithmetic series on the board: summing from (n - 1) down to 1 always yields exactly n(n - 1)/2.

Selection Sort Time Complexity Correct Key: D

#07. In embedded microcontrollers where writing to non-volatile EEPROM or Flash memory degrades the hardware, why is Selection Sort preferred over Insertion Sort?

A Selection Sort has a faster asymptotic time complexity of O(n log n).
B Selection Sort requires fewer comparisons than any other comparison sort.
C Selection Sort uses zero CPU registers during execution.
D Selection Sort performs at most n - 1 swaps (O(n) writes), minimizing physical wear on memory cells. ✓ Correct Answer
Step-by-Step Rationale & Proof:

While Insertion Sort can perform up to O(n²) memory shifts/writes, Selection Sort executes at most one swap per outer pass, totaling at most n - 1 swaps (O(n) memory writes). In hardware where flash write cycles degrade physical storage, minimizing writes is crucial.

💡 Classroom Talking Point:

Crucial real-world trade-off: when memory writes physically wear out hardware, O(n) swaps beats O(n²) shifts every time!

Insertion Sort Algorithm Correct Key: B

#08. What is the intuitive mechanical analogy most commonly used to explain how Insertion Sort operates?

A Dividing a deck of cards into two halves on a table and interleaving them.
B Sorting playing cards in your hand by sliding drawn cards into their correct ordered position. ✓ Correct Answer
C Looking up names in a telephone book using binary search.
D Pouring water through successive graduated filter cylinders.
Step-by-Step Rationale & Proof:

Insertion Sort mirrors how people arrange playing cards in their hands. As each new card (the 'key') is picked up, larger cards already held in the sorted hand are slid one slot to the right, and the key is inserted into its proper place.

💡 Classroom Talking Point:

Think of your left hand holding sorted cards, and your right hand drawing one new card at a time to insert.

Insertion Sort Algorithm Correct Key: C

#09. Why does the outer loop of Insertion Sort typically start at array index 1 instead of index 0?

A Index 0 is reserved for storing the length of the array in C-style arrays.
B The algorithm skips index 0 to avoid checking negative index bounds.
C A subarray consisting of a single element (arr[0]) is trivially already sorted. ✓ Correct Answer
D Index 0 always contains the global maximum element.
Step-by-Step Rationale & Proof:

A subarray of length 1 (namely arr[0..0]) satisfies the sortedness invariant trivially by definition. Therefore, the first meaningful insertion occurs when inserting the second element (arr[1]) into the 1-element sorted prefix.

💡 Classroom Talking Point:

A single card in your hand is already sorted; the sorting work starts when you draw card #2.

Insertion Sort Algorithm Correct Key: A

#10. How does Insertion Sort move elements to make room for the current key element?

A It shifts larger elements in the sorted portion one position to the right via consecutive assignments. ✓ Correct Answer
B It performs long-distance swaps between the key and the minimum element.
C It allocates a new dynamic linked list node for each preceding element.
D It rotates the entire array cyclically using a queue buffer.
Step-by-Step Rationale & Proof:

While scanning backward through the sorted prefix (while j >= 0 and arr[j] > key), Insertion Sort copies arr[j] into arr[j + 1]. This rightward shift creates a vacant slot where the key is eventually deposited.

💡 Classroom Talking Point:

Remember: Insertion Sort SHIFTS rather than SWAPS. One shift is a single assignment, saving CPU instructions.

Insertion Sort Algorithm Correct Key: D

#11. Why does standard Insertion Sort preserve the relative order of duplicate elements (making it a STABLE sort)?

A Because it uses a secondary hash table to track duplicate indices.
B Because it always swaps elements across even index intervals.
C Because the outer loop runs in reverse from n - 1 down to 0.
D Because the backward scan condition arr[j] > key stops when encountering an equal key, placing the key immediately after its duplicate. ✓ Correct Answer
Step-by-Step Rationale & Proof:

The shift condition arr[j] > key is strictly greater-than. When the key encounters an identical value in the sorted prefix, the condition evaluates to false, shifting halts, and the key is placed directly behind the duplicate, preserving original relative order.

💡 Classroom Talking Point:

Strict inequality (>) is the guardian of stability in Insertion Sort! Changing it to >= would make it unstable.

Insertion Sort Time Complexity (GFG) Correct Key: B

A O(n²) time with n(n - 1) / 2 comparisons and n shifts.
B O(n) linear time with exactly n - 1 comparisons and 0 shifts. ✓ Correct Answer

D O(1) constant time because no loops execute.

Because arr[i - 1] <= key, the inner while loop terminates immediately without shifting, requiring exactly n - 1 comparisons and 0 shifts, achieving O(n) time.

💡 Classroom Talking Point:

GFG benchmark: Best case is already sorted! Exactly n - 1 checks, 0 data movements, linear O(n) speed.

Insertion Sort Time Complexity (GFG) Correct Key: A

#13. In the AVERAGE CASE analysis grounded in GeeksforGeeks literature, why does Insertion Sort perform approximately n² / 4 shifts?

A On average, each key element is smaller than roughly half of the elements in the sorted subarray before finding its slot. ✓ Correct Answer
B Every key element always shifts past all preceding elements.
C The algorithm skips every second element during the backward scan.
D Only the left half of the array requires sorting.
Step-by-Step Rationale & Proof:

Per GeeksforGeeks: In a random permutation, a new key element will on average be smaller than about half of the elements currently in the sorted prefix of length i. The expected number of shifts is sum(i/2) = (1/2) * [n(n - 1)/2] ≈ n² / 4, which is Θ(n²).

💡 Classroom Talking Point:

Probability intuition: on average you walk halfway into your hand of cards before finding the right home for your new card.

Insertion Sort Time Complexity (GFG) Correct Key: C

#14. Under what input arrangement does the WORST CASE of Insertion Sort occur, and what is the total number of comparisons and shifts required?

A When all elements are zero; n - 1 comparisons.
B When elements alternate between odd and even numbers; n log2(n) operations.
C When the input is sorted in strict reverse order (e.g., [5, 4, 3, 2, 1]); requiring n(n - 1) / 2 comparisons and shifts. ✓ Correct Answer
D When the largest element is placed at index 1; requiring 2n operations.
Step-by-Step Rationale & Proof:

Per GeeksforGeeks: Worst case occurs when the array is in reverse order (e.g. [5, 4, 3, 2, 1]). Every new key arr[i] is smaller than all i elements in the sorted prefix. It must be compared and shifted past all of them to reach index 0. The total operations sum to 1 + 2 + ... + (n - 1) = n(n - 1) / 2, giving O(n²).

💡 Classroom Talking Point:

GFG reverse example: [5, 4, 3, 2, 1] causes every element to shift all the way to index 0, summing to n(n-1)/2.

Recursion and Divide-and-Conquer Correct Key: B

#16. Which sequence correctly lists the three foundational phases of the Divide-and-Conquer algorithmic design paradigm?

A Partition, Iterate, Finalize
B Divide (break into subproblems), Conquer (solve recursively), Combine (merge solutions) ✓ Correct Answer
C Select (find extreme), Swap (exchange), Verify (validate order)
D Transform, Conquer, Invert
Step-by-Step Rationale & Proof:

The Divide-and-Conquer paradigm consists of: 1) Divide the original problem into smaller subproblems that are smaller instances of the same problem; 2) Conquer the subproblems by solving them recursively (or directly at base cases); 3) Combine the solutions to form the overall answer.

💡 Classroom Talking Point:

The three D&C pillars: Divide into halves, Conquer down to base cases, Combine back together.

Recursion and Divide-and-Conquer Correct Key: A

#17. What is the vital role of the 'base case' in any recursive divide-and-conquer implementation?

A It establishes a terminating condition for trivial subproblem sizes to halt recursion and prevent call stack overflow. ✓ Correct Answer
B It sorts the entire array iteratively before recursive calls begin.
C It doubles the available memory on the runtime heap.
D It balances an unbalanced binary search tree.
Step-by-Step Rationale & Proof:

Every recursive call allocates a new stack frame on the call stack. The base case provides an exit condition for inputs small enough to be solved trivially (e.g., n <= 1). Without it, recursion continues indefinitely until call stack memory is exhausted.

💡 Classroom Talking Point:

Classroom analogy: A basecase is the brake pedal of recursion. Without brakes, you crash through the memory wall!

A Using a quadratic matrix equation.

A recurrence relation describes the running time T(n) of a recursive function in terms of T(k) for smaller input sizes k, plus the overhead cost f(n) of dividing the problem and combining the sub-solutions.

Recursion and Divide-and-Conquer Correct Key: C

#19. What is the key distinguishing factor between problems suited for Divide-and-Conquer versus those requiring Dynamic Programming?

A Divide-and-Conquer only applies to graphs, while Dynamic Programming only applies to strings.
B Dynamic Programming never uses recursion, whereas Divide-and-Conquer cannot be written iteratively.
C Divide-and-Conquer is best when subproblems are disjoint and independent; Dynamic Programming is required when subproblems overlap heavily. ✓ Correct Answer
D Divide-and-Conquer always runs in O(n²) time, whereas Dynamic Programming runs in O(1) time.
Step-by-Step Rationale & Proof:

Divide-and-Conquer partitions problems into disjoint, non-overlapping pieces (e.g. left and right halves of an array). When subproblems overlap and are recomputed repeatedly, Dynamic Programming avoids redundant work via memoization or tabulation.

💡 Classroom Talking Point:

Divide & Conquer = disjoint subproblems (no reuse needed). Dynamic Programming = overlapping subproblems (memoize!).

Merge Sort Algorithm Correct Key: B

#20. In Merge Sort, during which specific operational phase does all actual element comparison and sorting take place?

A During the recursive midpoint division step (mid = (left + right) / 2).
B During the Combine (Merge) step when comparing elements from two sorted subarrays into the main array. ✓ Correct Answer
C During the base case check (if left >= right).
D During initial memory pre-allocation.

Dividing an array in half does zero sorting—it merely partitions index ranges down to trivial 1-element subarrays. All comparisons and sorting decisions occur exclusively within the merge() procedure as it interleaves the two sorted halves.

Merge Sort Algorithm Correct Key: A

#21. What is the time complexity of merging two sorted subarrays having a combined length of n elements using the standard two-pointer merge algorithm?

A O(n) linear time ✓ Correct Answer
B O(log n) logarithmic time
C O(n²) quadratic time
D O(1) constant time
Step-by-Step Rationale & Proof:

The two-pointer merge algorithm advances one of two pointers on each step, comparing L[i] and R[j] and copying the smaller element to the destination array. Each of the n elements is inspected and written at most once, requiring linear O(n) time.

💡 Classroom Talking Point:

Two pointers move forward without ever backtracking. Each step places one item, taking linear O(n) time.

Merge Sort Algorithm Correct Key: D

#22. In the standard two-pointer merge() routine, which comparison operator ensures that identical elements maintain their relative original order, guaranteeing STABILITY?

A L[i] < R[j] (strictly less-than)
B L[i] != R[j] (not-equal)
C L[i] > R[j] (strictly greater-than)
D L[i] <= R[j] (less-than-or-equal, prioritizing the left subarray on ties) ✓ Correct Answer
Step-by-Step Rationale & Proof:

When comparing L[i] and R[j], writing 'if (L[i] <= R[j])' ensures that if equal elements appear in both subarrays, the one from the left subarray L is copied first. Because elements in L originally preceded elements in R, their relative order is preserved.

💡 Classroom Talking Point:

Remember the condition: 'if L[i] <= R[j], pick L[i]'. The '<=' guarantees stability by favoring the left side on ties!

Merge Sort Recursion Tree & Complexity Correct Key: C

#23. For an input array of size n, what is the total height (number of levels) of the Merge Sort recursion tree?

A n levels
B n / 2 levels
C log2(n) + 1 levels (which is Θ(log n)) ✓ Correct Answer
D n² levels
Step-by-Step Rationale & Proof:

At each level of recursion, the problem size is halved: n, n/2, n/4, ..., down to 1. The number of times you can divide n by 2 until reaching 1 is log2(n). Including the root level, the total tree height is log2(n) + 1, which is O(log n).

💡 Classroom Talking Point:

Every time you cut something in half repeatedly until size 1, the number of cuts is logarithmic: log2(n).

Merge Sort Recursion Tree & Complexity Correct Key: B

#24. In the Merge Sort recursion tree, how much total merging work is performed across all nodes at ANY single level k?

A O(1) work
B Exactly c · n work (linear O(n) across all subproblems at that level) ✓ Correct Answer
C O(n²) work
D O(log n) work
Step-by-Step Rationale & Proof:

At level k, there are 2^k subproblems, each of size n / 2^k. The merging cost per subproblem is c · (n / 2^k). Multiplying them gives 2^k · c · (n / 2^k) = c · n work. Every single level contributes exactly O(n) total work!

💡 Classroom Talking Point:

Crucial classroom concept: 'Every level of the recursion tree sums up to exactly n elements, so every level costs O(n).'

Merge Sort Recursion Tree & Complexity Correct Key: D

#25. Applying the Master Theorem to the Merge Sort recurrence T(n) = 2T(n/2) + Θ(n), which case applies and what is the resulting asymptotic bound?

A Case 1: T(n) = Θ(n)
B Case 3: T(n) = Θ(n²)
C Case 1: T(n) = Θ(log n)
D Case 2 (f(n) = Θ(n^(log_b a)) where log2(2) = 1): T(n) = Θ(n log n) ✓ Correct Answer
Step-by-Step Rationale & Proof:

Here a = 2, b = 2, and f(n) = Θ(n). Since log_b(a) = log_2(2) = 1, we have n^(log_b a) = n^1 = n. Because f(n) = Θ(n^1), Case 2 of the Master Theorem applies, yielding T(n) = Θ(n^(log_b a) · log n) = Θ(n log n) across all cases.

💡 Classroom Talking Point:

Master Theorem Case 2: when work per level stays constant across all tree levels, total work is level cost × tree height = O(n log n).

#29. Why is Merge Sort particularly well-suited for sorting singly linked lists compared to arrays?
